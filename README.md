# Wonslate（万邦译）

[中文](README.zh-CN.md) | **English**

> A local, offline, commercially-usable multi-engine smart translation engine (**v0.0.1**).

Wonslate is a **privacy-first** local translation app: data never leaves the device, requests are served through multi-engine smart routing, and built-in translation memory (TM) with AI distillation keeps lowering the cost of repeated translations.

## Architecture

```
WPF UI (C#)  <-->  Router (rule-based)  <-->  EngineNative (FFI)  <-->  Rust translator_engine
                                                     │
                                              demo engine (built-in glossary)
                                              argos / madlad (local sidecar slots)
```

- **.NET 10**: business logic, static routing rules, WPF UI
- **Rust (cdylib)**: engine adapter layer, C ABI exporting `tt_translate` / `tt_version` / `tt_free_string`
- Results are returned as JSON; strings are allocated in Rust and freed by .NET after use

## Layout

```
Wonslate/
├─ translator-engine/          # Rust crate (cdylib): engine / routing / TM / distill core
│  └─ src/
│     ├─ lib.rs                # C ABI exports + panic guard
│     └─ engine/               # Translator trait + engine registry + demo engine
├─ Wonslate.UI/                # .NET 10 WPF client (builds Wonslate.exe)
│  ├─ Interop/EngineNative.cs  # P/Invoke bindings
│  ├─ Sidecar/                 # local sidecar process manager
│  └─ ViewModels/MainViewModel.cs
├─ Wonslate.UI.Tests/          # xUnit tests for the .NET client
├─ build.bat                   # Windows one-click entry (forwards to script/build.py)
├─ build.sh                    # Linux/macOS one-click entry
└─ script/build.py             # cross-platform build/test core (Python)
```

## Build

Requires Rust 1.98+ and .NET SDK 10.0+ (the WPF client builds on Windows only). Python 3
is used by the build/test entrypoint and the FFI smoke tests.

```bash
python script/build.py            # build: Rust engine (release) + WPF app on Windows
python script/build.py --test     # build, then every test layer (Rust / .NET / Python FFI / sidecar e2e)
python script/build.py --unit     # build, then Rust + .NET tests only
python script/build.py --ffi      # build, then the Python FFI smoke only
python script/build.py --run      # build, then launch Wonslate.exe (Windows)
```

`build.bat` (Windows) and `build.sh` (Linux/macOS) are thin per-OS entrypoints that
forward every argument to `script/build.py`. Outputs land in
`translator-engine/target/release/` (native library, e.g. `translator_engine.dll`) and
`Wonslate.UI/bin/Release/net10.0-windows/` (`Wonslate.exe`); both are generated by local
or CI builds and never committed.

## Try it (demo engine)

The built-in `demo` engine carries a small en<->zh glossary so the whole
`WPF -> FFI -> Rust` path can be exercised with **no model downloads**. Launch the app,
keep privacy mode on, and check these inputs — every output below is measured from the
shipped binary (`mode=realtime`, `privacy=true`, `engine=demo`), not an aspiration:

| Input | Pair | Output |
|---|---|---|
| `hello` | en -> zh | `你好` |
| `hello there` | en -> zh | `你好` |
| `good morning` | en -> zh | `早上好` |
| `good night` | en -> zh | `晚安` |
| `i love the world` | en -> zh | `i love 这个 世界` |
| `你好` | zh -> en | `hello` |
| `你好世界` | zh -> en | `hello world` |

`i love the world` is listed on purpose: words the glossary does not know are passed
through unchanged, so the demo engine demonstrates word-level substitution rather than
translation. The other registered engines need their own prerequisites: `argos` and
`madlad` talk to a local sidecar (`sidecar/ct2_sidecar.py`, which ships a mock backend —
loading a real CTranslate2/Argos checkpoint is still open), and `ollama` needs a running
Ollama with a pulled model.

## Security

Wonslate is privacy-first: translation data never leaves the device. If you believe you found a security issue, please report it privately — see [SECURITY.md](SECURITY.md). Do **not** open a public issue.
